# ACM 1.18.0：寬差距縮減、先遮工具結果、使用者訊息進標記

2026-11-11 由 Claude 依使用者直接授權實作並切為現用入口。本頁是 1.18.0 的行為說明與移植須知；
`docs/ACM_SESSION.md` 與 README 裡「保留目標 n−1」「任務錨點」的敘述已過時，以本頁為準。

## 為什麼改

量測對象是一個長時間製作用的 Pi session（2026-11-09 至 11-11，3,660 次模型呼叫，ACM 1.16.0）。

| 量到的事 | 數字 |
| --- | --- |
| 縮減次數 | 461 |
| 每次縮減移出 | 中位數約 9K token |
| 縮減間隔 | 約每 8 次呼叫 |
| 縮減後那次請求快取全部失效 | 461 次中 456 次 |
| 這些請求的未快取輸入 | 約 9,400 萬 token，佔全部未快取輸入的 95% |

原因是保留目標固定為觸發值減 1 個百分點。每次縮減都會改動請求前段，供應商的前綴快取整份作廢；
差距只有 1 個百分點時，等於每 8 次呼叫就用全價重讀一次整個視窗。

另一個問題：1.16.0 把對話第一則使用者訊息當任務錨點永久保留。縮減後它出現在視窗最前面，
後面的回覆已經移出，模型曾把它誤認成新的提問（工具 session 的 Graphify 事件）。

## 1.18.0 的行為

1. **保留目標固定為觸發值的一半。** 請求當下由觸發值算出，所有對話與新對話預設都適用。
   已保存的舊 `targetPercent`（例如 25／24、15／14、70／55）位元組不改寫，但不再使用。
   選單與控制仍只輸入單一數字 n；明確輸入時保存 n 與 n/2。
2. **縮減分兩層，同一次完成。** 由新往舊：先在保留目標的一半內保留全文；
   更舊的部分保留模型文字與工具呼叫，工具結果換成開頭 200 字加一行說明，圖片移除；
   再放不下才整組移出。160 token 以下的工具結果不遮。
3. **不再釘第一則訊息。** 已移出視窗的較早使用者訊息由程式整理進開頭標記，依時間排列，
   註明當時已處理、不是新的請求。每則最多 500 字，總量上限為保留目標的 4%（最多 6,000 token），
   放不下時保留較新的並標示省略數量。最新的使用者訊息仍是真正的訊息。
4. **標記改寫。** 說明較早內容已移出、被遮的結果可以重讀或重跑、原始紀錄檔的位置。
5. 沒有 AI 摘要、沒有額外模型請求、不新增模型工具、不對代理下新指令。原始 session 紀錄不變。

快取相關的不變量：兩次縮減之間，每個請求都只在前一個請求後面追加。遮罩邊界 `fullFromId`
隨 `acm-passive` 一起保存；遮罩文字與使用者訊息清單都只由「哪些列在視窗外」決定，
用未校準的計數器計算，所以每次請求位元組相同，重啟後也相同。

## 驗證

- 新測試 47 項，在 Pi SDK 1.1.0 與本機安裝的 1.5.2 都通過。
- 既有 ACM 測試加新測試共 276 項，在 1.1.0 通過。
- 切換入口後全套 `tests/*.test.mjs` 加 `modules/acm/tests/*.test.mjs`：1,246 項中 1,234 通過、11 略過、1 失敗。
  失敗的是 `tests/bundle.test.mjs` 第 23 行，斷言現用 ACM 版本為 `'1.16.0'`，現在是 `'1.18.0'`。這個檔案沒有改，留給整合時更新。
- 整合測試直接驗證：84 次請求中，前綴被改動的次數等於縮減次數；重啟後送出的請求以前一個請求為前綴；
  1.16.0 縮減過的對話在 1.18.0 下繼續，沒有失敗。
- 真實紀錄離線回放（複製檔、離線假模型，不連網）：

| | 製作 session | 工具 session |
| --- | --- | --- |
| 升級後第一次請求 | 無錯誤、不縮減 | 無錯誤、不縮減 |
| 1.16.0 視窗（約 24 萬 token） | 85 個模型回合 | 83 個模型回合 |
| 1.18.0 縮減後（約 12.7 萬 token） | 76 個回合，其中 26 個全文 | 62 個回合，其中 24 個全文 |

| 標記列出的較早使用者訊息 | 72 則 | 40 則 |
| 縮減後接續 4 次請求的前綴改動 | 0 | 0 |

沒有驗證的事：真實供應商的快取命中率與實際扣的額度。上面只證明請求前綴穩定，這是命中快取的前提。

## 還原

把 `modules/acm/extensions/index.ts` 改回 `export {default} from './index_v1.16.0.ts';`，閒置時 reload。
1.18.0 寫入的 `acm-passive` 紀錄多一個 `fullFromId` 欄位，1.16.0 會忽略它。

## 0.17 候選移植須知

候選工作區的 ACM 1.17.0 疊在 1.16.0 的選窗上，移植時：

1. `index_v1.17.0.ts` 依 `index_v1.18.0.ts` 對 1.16.0 的差異套用同樣的修改
   （`window_v1.6.0`、`threshold_v1.18.0`、`refreshPolicy`、`sourceRows`、`normalize`、選窗呼叫、標記、候選狀態、`boundaryKey`）。
2. `menu_v1.17.0.mjs`、`controls_v1.17.0.mjs` 的 `parseThreshold` 改由 `threshold_v1.18.0.mjs` 匯入，
   顯示與說明文字的 n−1 改成 n 的一半；控制中心顯示比例時用 `triggerPercent * TARGET_SHARE`。
3. 斷言 n−1 的候選測試（`acm117-owner-sdk`、`control170-acm-actions` 等）改成 n/2。
4. `MODULES.json`、CHANGELOG、README、`docs/ACM_SESSION.md` 尚未更新。
5. 選窗、遮罩、標記、目標比例的行為已由使用者定案，移植時不要改動；發現問題先回報使用者。
